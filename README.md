# ArchiveBuddy

A private, on-device iOS app that lets you photograph pages from physical journals or notebooks, extract the handwritten text via a hybrid OCR pipeline, and then chat with your archived content using AI. Everything runs locally — no internet connection, no external API calls.

## Requirements

- Xcode 16.0+
- iOS 26.0+ deployment target
- iPhone 15 Pro or newer (Apple Intelligence required)

## Getting Started

1. Clone the repo and open `ArchiveBuddy.xcodeproj` in Xcode.
2. SPM dependencies resolve automatically on first build.
3. Select a connected device or simulator supporting Apple Intelligence.
4. Press `Cmd+R`.

**CLI build:**
```bash
xcodebuild -project ArchiveBuddy.xcodeproj -scheme ArchiveBuddy -configuration Debug build
```

## How It Works

### 1. Photo → Text (OCR Pipeline)

When you add a page photo, `OCRPipeline` runs two passes in sequence:

- **Stage 1 — Apple Vision** (`VNRecognizeTextRequest` at `.accurate` level) reads the handwriting, producing raw text and a per-word confidence score.
- **Stage 2 — FoundationModels cleanup** passes the raw text to an on-device `LanguageModelSession` with a short prompt asking it to correct obvious OCR errors without changing the meaning.

The photo is never saved to disk. Only the cleaned text survives into the database. Words below a 0.5 confidence threshold are flagged for optional user review before the page is committed.

### 2. Text → Searchable Vector (RAGModel)

Confirmed text is chunked by `DocumentProcessor` (sentence-aligned chunks with overlap; sentences over the limit are split into word windows so no text is dropped) and each chunk is converted into a vector embedding:

1. Split chunk into words.
2. Look up each word in Apple's `NLEmbedding` (built-in semantic word model).
3. Average all word vectors using Accelerate (`vDSP`) for performance.

Each vector is stored in **SVDB** (a local vector database) alongside a `__META__` header encoding the chunk's page ID, archive ID, archive title, page number, and user-defined date. There is one SVDB collection per archive, keyed by `archive.id.uuidString`. Chunk text is also persisted to SQLite (`page_chunks` table) so the SVDB collection can be rebuilt from scratch if lost.

### 3. Chat Query → Relevant Pages (ArchiveQueryService)

When you ask a question in chat:

1. Your question is embedded using the same NLEmbedding + Accelerate pipeline.
2. `ArchiveQueryService` fans out a concurrent semantic similarity search across every selected archive using a `TaskGroup` (one `RAGModel.findLLMNeighbors` call per archive).
3. All results are merged, sorted by similarity score, and the top 5 are kept.
4. The `__META__` headers are parsed to extract citation data (archive title, page number, date) and stripped from the text before it reaches the LLM.

### 4. Context + Question → Answer (LLM)

The retrieved excerpts and your question are assembled into an augmented prompt, which is passed to `LLM.streamResponse`. `LLM` manages a `LanguageModelSession` per chat session, streams tokens back to the UI, and saves the completed message with its structured `[PageCitation]` to SQLite. If the context window fills, it condenses the transcript using a first+last strategy and retries.

Session titles are auto-generated by a throwaway `LanguageModelSession` after the first response, keeping the title prompt out of the chat transcript.

## Architecture

MVVM + SwiftUI. Services are instantiated once at the composition root (`ArchiveBuddyApp.swift`) and injected via `.environment()`. ViewModels receive services through their own `init` — they never access `@Environment` directly.

```
ArchiveBuddy/
├── ArchiveBuddyApp.swift          composition root — wires and injects all services
├── Models/
│   ├── Archive.swift
│   ├── Page.swift
│   ├── PageDraft.swift            transient type passed to DatabaseManager.insertPage()
│   ├── PageCitation.swift         returned alongside LLM responses; stored as JSON in chat_messages
│   ├── ChatSession.swift
│   └── ChatMessage.swift
├── Services/
│   ├── DatabaseManager.swift      GRDB SQLite wrapper; owns atomic pageNumber assignment
│   ├── RAGModel.swift             one SVDB collection per archive; embedding + search
│   ├── OCRPipeline.swift          Vision OCR → FoundationModels cleanup; stateless
│   ├── ArchiveQueryService.swift  multi-archive fan-out, merge/re-rank, prompt builder
│   └── LLM.swift                  session-aware generation; no archive knowledge
├── ViewModels/
│   ├── ArchiveListViewModel.swift
│   ├── PageIngestionViewModel.swift
│   └── ChatViewModel.swift
└── Views/
    ├── ContentView.swift
    ├── ArchiveListView.swift
    ├── ArchiveDetailView.swift
    ├── AddPagesView.swift
    ├── CreateArchiveView.swift
    ├── ChatListView.swift
    ├── ChatView.swift
    └── NewChatView.swift
```

**Database:** `~/Documents/archive_buddy.sqlite3` managed via GRDB `DatabaseMigrator`.

| Table | Contents |
|---|---|
| `archives` | id, title, description, createdAt |
| `pages` | id, archiveId, pageNumber, userDefinedDate, uploadedAt, finalText, isEmbedded |
| `page_chunks` | id, pageId, archiveId, chunkText, chunkIndex, isEmbedded |
| `chat_sessions` | id, title, selectedArchiveIds (JSON), createdAt, updatedAt, transcriptJSON |
| `chat_messages` | id, sessionId, text, isUser, timestamp, citations (JSON) |

**Key SPM dependencies:**

| Package | Purpose |
|---|---|
| `groue/GRDB.swift` | SQLite ORM — native UUID support, Codable conformance, transaction safety |
| `SVDB` | Semantic vector database — one collection per archive |
| `MarkdownUI` | Markdown rendering in chat |

## Development & Sample Data

In `DEBUG` builds, `ArchiveBuddyApp.init()` automatically calls `SampleData.seedIfNeeded(db:)` on launch. This populates the database with three pre-built archives and fully-embedded pages so you can develop against realistic content without having to photograph anything.

**Sample archives:**

| Archive | Content |
|---|---|
| Italy Trip — June 2023 | Three travel journal entries from Rome, Florence, and the Amalfi Coast |
| Book Notes — Thinking, Fast and Slow | Two pages of reading notes on Kahneman's System 1/2 model and prospect theory |
| Personal Diary — Spring 2024 | Two personal diary entries covering daily life, running, and family |

Each page is 300–500 words, which produces 2+ chunks per page and exercises multi-chunk retrieval in the RAG pipeline.

**Seeding behaviour:**

- On first launch (empty DB): seeds all archives.
- If DB already has data at the same version: skips seeding.
- If `SampleData.currentVersion` has been bumped: wipes all existing archives (including their SVDB collections) and reseeds from scratch.

To force a full reseed during development, increment `currentVersion` in `ArchiveBuddy/Debug/SampleData.swift`:

```swift
static let currentVersion = 2  // bump to wipe and reseed on next launch
```

`SampleData.swift` is wrapped in `#if DEBUG` and is excluded from Release builds at compile time.

## Testing

**Run tests:**
```bash
xcodebuild -project ArchiveBuddy.xcodeproj -scheme ArchiveBuddyTests test
xcodebuild -project ArchiveBuddy.xcodeproj -scheme ArchiveBuddyUITests test
```

There are no mocked services — tests run against real instances. `DatabaseManager` opens an in-memory GRDB queue in test targets so tests do not touch the on-disk database.

> Note: `OCRPipeline` and `LLM` require Apple Intelligence and cannot run on the simulator. Tests for those components must be run on a physical device (iPhone 15 Pro or newer).
